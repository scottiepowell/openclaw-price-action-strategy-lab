# Runbook

## Purpose

Operate the Strategy Lab as a documentation-first validation workspace.

## Common actions

- Check repository status
- Validate manifests and placeholders
- Review replay cases
- Review paper-validation readiness

## Typical workflow

1. Check the current TODO/status summary.
2. Pick the highest-value missing doc or artifact.
3. Keep evidence references explicit.
4. Update the relevant report or checklist.
5. Verify the result with a light sanity check.

## When to pause

- evidence is missing
- a label would be speculative
- a candidate is drifting toward live-trading language
- the source manifest does not support the claim

## Boundaries

- No live trading
- No execution steps

## Good defaults

- favor traceability over brevity
- prefer conservative labels
- keep paper-only language separate from live-readiness language
